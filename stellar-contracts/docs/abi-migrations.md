# Contract ABI & Storage-Key Migration Notes

This file is the changelog for **intentional** changes to the PetChain
Soroban contract's public interface (`stellar-contracts/src/lib.rs`).

Two automated guards exist to catch *unintentional* changes:

- **ABI snapshot** (`stellar-contracts/abi-snapshot.txt`, generated by
  `scripts/generate_abi_snapshot.sh`): a normalized list of every `pub fn`
  signature in the `#[contractimpl]` block. CI (`abi-snapshot` job) fails a
  PR if the generated snapshot no longer matches the committed file.
- **Discriminant stability tests**
  (`src/test_discriminant_stability.rs`): exhaustive `match` expressions
  over every storage-key enum (`DataKey`, `InsuranceKey`, `DisputeKey`,
  etc.). Renaming, removing, or adding a variant fails to compile until the
  match (and, for the tests, the pinned tag) is updated here.

If either guard fires in your PR:

1. Confirm the change is intentional (not an accidental signature edit or
   variant rename).
2. Run `./scripts/generate_abi_snapshot.sh` to refresh `abi-snapshot.txt`,
   and update `src/test_discriminant_stability.rs` for any storage-key enum
   change.
3. Add an entry below describing the change and its ledger-compatibility
   impact.

Treat every storage-key enum (`DataKey` and the domain-specific `*Key`
enums) as append-only: add new variants at the end, and never rename,
remove, or reorder an existing one without a migration entry here — do not
assume it is safe just because a given variant carries no explicit
discriminant, since Soroban's exact on-the-wire representation for a
mixed-variant enum is an SDK implementation detail this document does not
depend on. `ContractError` discriminants are explicit and numeric
(`#[repr(u32)]`); new variants must use unused values and never renumber
existing ones, since off-chain integrators match on the numeric code.

## Log

### 2026-08-26 — Typed errors for former panic!/assert! sites (Issues #1146–#1150)

- Fixed a pre-existing compile bug: `ContractError::RecordAlreadyDeleted` was
  declared twice (values 161 and 163). Removed the unused second
  declaration; it was never referenced anywhere and could not have compiled
  or shipped, so no live discriminant changed.
- Added five new `ContractError` variants for dispute handling that
  previously used raw `panic!`/`assert!` with string messages:
  `DisputeNotFound` (164), `DisputeNotOpenForVoting` (165),
  `NotDisputeStakeholder` (166), `NotInEvidencePhase` (167),
  `NotDisputeParty` (168). All existing variant values are unchanged.
- No public function signatures changed — `abi-snapshot.txt` reflects the
  pre-existing public ABI.
- Added `src/test_discriminant_stability.rs`, pinning the variant set of
  all 24 storage-key enums, and this migration log + the CI diff job that
  enforces it going forward.

**Threat-model note:** these changes only affect *how* an already-checked
invalid state is reported (a typed, documented error code instead of an
opaque panic string or an assertion failure). No authorization check,
storage layout, or success-path behavior was modified — every converted
site still aborts the transaction on the same condition it did before.
