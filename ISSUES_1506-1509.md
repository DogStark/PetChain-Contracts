### Issue #1506: Add event-to-state reconciliation utility
**Scope**: Build a deterministic tool that replays contract events and compares reconstructed pet, consent, vaccination, and insurance state with snapshots.

**Problem Statement**:
Events are the source of truth for blockchain state changes, but state can become inconsistent if:
- Events are processed out of order
- State updates fail silently
- Replay logic differs from original execution
- Storage migrations don't properly reconstruct history

**Proposed Solution**:

#### 1. Create Event Replay Module
**Location**: `stellar-contracts/src/event_replay.rs` or `contracts/shared/event_replay.rs`

**Core Components**:

### Issue #1507: Add malicious-token integration fixture for adoption escrow
**Scope**: Add a token test contract that fails, lies about transfer behavior, or attempts callback reentry; verify the adoption contract preserves escrow invariants.

**Problem Statement**:
The adoption escrow interacts with arbitrary token contracts. Malicious tokens could:
- Return `true` for failed transfers
- Not actually transfer tokens but claim success
- Call back into the escrow during transfer (reentrancy)
- Drain escrow by exploiting state inconsistencies

**Current Escrow Location**: `stellar-contracts/contracts/pet-transfer-adoption/src/escrow.rs`

**Proposed Solution**:

#### 3. Escrow Hardening
Ensure escrow has proper defenses:
```rust
// In escrow.rs
pub fn release(env: Env, escrow_id: BytesN<32>) -> Result<(), EscrowError> {
    // 1. Check reentrancy guard
    if env.storage().instance().has(&REENTRANCY_GUARD) {
        return Err(EscrowError::ReentrantCall);
    }
    env.storage().instance().set(&REENTRANCY_GUARD, &true);
    
    // 2. Verify state before transfer
    let escrow = get_escrow(&env, &escrow_id)?;
    require!(escrow.state == EscrowState::Active, EscrowError::InvalidEscrowState);
    
    // 3. Mark state as "releasing" before external call
    update_escrow_state(&env, &escrow_id, EscrowState::Releasing);
    
    // 4. Attempt transfer
    let token_client = token::Client::new(&env, &escrow.token);
    let transfer_result = token_client.try_transfer(
        &escrow.buyer,
        &escrow.seller,
        &escrow.amount,
    );
    
    // 5. Verify transfer succeeded by checking balances
    let seller_balance_after = token_client.balance(&escrow.seller);
    require!(
        seller_balance_after >= expected_balance,
        EscrowError::TransferFailed
    );
    
    // 6. Only update to Released if all checks pass
    update_escrow_state(&env, &escrow_id, EscrowState::Released);
    
    // 7. Clear reentrancy guard
    env.storage().instance().remove(&REENTRANCY_GUARD);
    
    Ok(())
}
```

### Issue #1508: Add deterministic chain-mismatch failure tests
**Scope**: Ensure calls and manifests fail with clear errors when deployment network, chain ID, or contract address metadata do not match.

**Problem Statement**:
Contracts deployed to wrong networks or with incorrect metadata can:
- Accept transactions on unintended chains
- Reference wrong contract addresses in cross-contract calls
- Fail silently with cryptic errors
- Leak testnet keys to mainnet

**Proposed Solution**:

#### 1. Chain ID Verification Module
**Location**: `stellar-contracts/src/chain_verification.rs`

```rust
#[derive(Clone, Copy, PartialEq, Eq)]
pub enum NetworkId {
    StellarMainnet,
    StellarTestnet,
    StellarFuturenet,
    CeloMainnet,
    CeloAlfajores,
}

pub struct ContractDeploymentMetadata {
    pub network: NetworkId,
    pub chain_id: String,
    pub deployed_at: u64,
    pub contract_hash: BytesN<32>,
}

impl ContractDeploymentMetadata {
    pub fn verify_network(&self, env: &Env) -> Result<(), ChainMismatchError> {
        let current_network = detect_network(env)?;
        
        if current_network != self.network {
            return Err(ChainMismatchError::NetworkMismatch {
                expected: self.network,
                actual: current_network,
            });
        }
        
        Ok(())
    }
    
    pub fn verify_contract_address(
        &self,
        env: &Env,
        expected_address: &Address,
    ) -> Result<(), ChainMismatchError> {
        let actual_address = env.current_contract_address();
        
        if &actual_address != expected_address {
            return Err(ChainMismatchError::AddressMismatch {
                expected: expected_address.clone(),
                actual: actual_address,
            });
        }
        
        Ok(())
    }
}

pub enum ChainMismatchError {
    NetworkMismatch { expected: NetworkId, actual: NetworkId },
    AddressMismatch { expected: Address, actual: Address },
    ChainIdMismatch { expected: String, actual: String },
    ManifestVersionMismatch { expected: u32, actual: u32 },
}
```

### Issue #1509: Add contract release compatibility report
**Scope**: Generate a release report listing ABI changes, storage schema versions, error-code changes, and deployment-manifest deltas.

**Problem Statement**:
Contract upgrades can break:
- Frontend/backend integrations (ABI changes)
- Existing state (storage schema changes)
- Error handling (new/removed error codes)
- Deployment automation (manifest changes)

Need automated detection of breaking vs. non-breaking changes.

**Proposed Solution**:

#### 1. Compatibility Report Generator
**Location**: `stellar-contracts/scripts/generate-release-report.sh`

```bash
#!/usr/bin/env bash
# Generate compatibility report between two versions

set -euo pipefail

PREV_VERSION="${1:-}"
CURR_VERSION="${2:-HEAD}"
OUTPUT="${3:-release-report.md}"

if [ -z "$PREV_VERSION" ]; then
  echo "Usage: $0 <previous-version> [current-version] [output-file]"
  exit 1
fi

# 1. ABI Changes
echo "## ABI Changes" > "$OUTPUT"
diff \
  <(git show "$PREV_VERSION:abi-snapshot.txt") \
  <(git show "$CURR_VERSION:abi-snapshot.txt") \
  | grep -E '^[<>]' \
  >> "$OUTPUT" || true

# 2. Storage Schema Changes
echo "## Storage Schema Changes" >> "$OUTPUT"
./scripts/compare-storage-schemas.sh "$PREV_VERSION" "$CURR_VERSION" >> "$OUTPUT"

# 3. Error Code Changes
echo "## Error Code Changes" >> "$OUTPUT"
diff \
  <(git show "$PREV_VERSION:error-codes.json" | jq -r '.enums[].errors[] | "\(.code) \(.name)"') \
  <(git show "$CURR_VERSION:error-codes.json" | jq -r '.enums[].errors[] | "\(.code) \(.name)"') \
  >> "$OUTPUT" || true

# 4. Deployment Manifest Changes
echo "## Deployment Manifest Changes" >> "$OUTPUT"
diff \
  <(git show "$PREV_VERSION:deployment-manifest.json") \
  <(git show "$CURR_VERSION:deployment-manifest.json") \
  >> "$OUTPUT" || true

# 5. Breaking Change Analysis
echo "## Breaking Changes" >> "$OUTPUT"
./scripts/detect-breaking-changes.sh "$PREV_VERSION" "$CURR_VERSION" >> "$OUTPUT"

echo "Report generated: $OUTPUT"
```

#### 2. Breaking Change Detector
**Location**: `stellar-contracts/scripts/detect-breaking-changes.sh`

```bash
#!/usr/bin/env bash
# Detect breaking changes between versions

PREV="$1"
CURR="$2"

BREAKING=0

# Check for removed functions (breaking)
REMOVED_FUNCTIONS=$(comm -23 \
  <(git show "$PREV:abi-snapshot.txt" | grep "^fn " | sort) \
  <(git show "$CURR:abi-snapshot.txt" | grep "^fn " | sort))

if [ -n "$REMOVED_FUNCTIONS" ]; then
  echo "### BREAKING: Removed Functions"
  echo "$REMOVED_FUNCTIONS"
  BREAKING=1
fi

# Check for changed function signatures (breaking)
CHANGED_SIGNATURES=$(diff \
  <(git show "$PREV:abi-snapshot.txt" | grep "^fn ") \
  <(git show "$CURR:abi-snapshot.txt" | grep "^fn ") | grep "^<" || true)

if [ -n "$CHANGED_SIGNATURES" ]; then
  echo "### BREAKING: Changed Function Signatures"
  echo "$CHANGED_SIGNATURES"
  BREAKING=1
fi

# Check for retired error codes (potentially breaking)
RETIRED_ERRORS=$(jq -r '
  .enums[].retired[] | "Code \(.code): \(.name)"
' "error-codes.json")

if [ -n "$RETIRED_ERRORS" ]; then
  echo "### WARNING: Retired Error Codes"
  echo "$RETIRED_ERRORS"
fi

# Check for storage version bump (requires migration)
PREV_STORAGE_VERSION=$(git show "$PREV:src/storage_version.rs" | grep "pub const VERSION" | grep -oP '\d+')
CURR_STORAGE_VERSION=$(git show "$CURR:src/storage_version.rs" | grep "pub const VERSION" | grep -oP '\d+')

if [ "$CURR_STORAGE_VERSION" -gt "$PREV_STORAGE_VERSION" ]; then
  echo "### REQUIRES MIGRATION: Storage version bump $PREV_STORAGE_VERSION → $CURR_STORAGE_VERSION"
  BREAKING=1
fi

exit $BREAKING
```
